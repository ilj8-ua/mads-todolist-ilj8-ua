🔹 ¿Por qué `new HashSet<>()` al borrar equipo? Para evitar ConcurrentModificationException al borrar elementos de la colección mientras se itera sobre ella.

🔹 ¿Por qué LAZY en `@ManyToMany`? Para no traer a memoria todos los usuarios y sus tareas cada vez que solo consultas el nombre del equipo (evita problemas N+1 y consumo de RAM).

Preguntas Trampa del Profesor (Defensa Oral)
❓ 1. ¿Por qué en los tests de repositorio pusisteis @Transactional pero en los de servicio no?
Respuesta: En los tests de repositorio (EquipoTest) se usa para que Hibernate mantenga abierta la sesión durante las comprobaciones de persistencia y haga rollback automático al terminar cada test. En cambio, en EquipoServiceTest no se debe poner porque el test debe simular el entorno real del controlador web; si pusiéramos @Transactional en el test, taparíamos fallos reales como que a algún método del servicio se le hubiera olvidado poner su propio @Transactional o accesos perezosos fuera de sesión.
❓ 2. ¿Cómo evitasteis borrar los usuarios al eliminar un equipo?
Respuesta: 1. La relación @ManyToMany no tiene CascadeType.REMOVE ni ALL hacia los usuarios.
2. En eliminarEquipo(), antes de llamar a equipoRepository.delete(equipo), iteramos sobre los miembros y llamamos a equipo.removeUsuario(usuario). Esto borra las filas de la tabla intermedia equipo_usuario sin tocar la tabla usuarios.
❓ 3. ¿Por qué se usa `new HashSet<>(equipo.getUsuarios())` al desvincular?
Respuesta: Si iterásemos directamente sobre equipo.getUsuarios() y dentro del bucle llamásemos a equipo.removeUsuario(), estaríamos modificando la misma colección que el iterador está recorriendo, lanzando una ConcurrentModificationException. Crear un new HashSet<>() nos da una copia defensiva para iterar de forma segura.
❓ 4. ¿Por qué tenéis dos workflows en GitHub Actions?
Respuesta: • developer-tests.yml corre con H2 en memoria: feedback ultra rápido (30 seg) para el desarrollador en cada push.
• integration-tests.yml arranca un contenedor PostgreSQL 13 en red con services: y pg_isready: valida que el dialecto real y la base de datos de producción funcionen antes de mezclar el Pull Request.
❓ 5. Si un usuario no admin manda un POST con Postman a `/equipos/1/eliminar`, ¿qué pasa?
Respuesta: El endpoint invoca el método privado comprobarAdmin() en EquipoController. Al detectar que el usuario no tiene admin == true, lanza UsuarioNoAutorizadoException, que devuelve un HTTP 401 Unauthorized. La acción se bloquea en backend independientemente de la interfaz web.
❓ 6. ¿Por qué usamos DTOs (EquipoData) en lugar de pasar la entidad a la vista?
Respuesta: 1. Evita LazyInitializationException al renderizar colecciones fuera de la transacción.
2. Evita ataques de Mass Assignment y fugas de datos sensibles.
3. Desacopla la vista de los cambios en las tablas de la BD. Mapeamos con ModelMapper.
❓ 7. ¿Por qué se usa `readOnly = true` en métodos de consulta?
Respuesta: Informa a Hibernate de que no se van a modificar entidades. Hibernate desactiva el dirty checking (comprobación de cambios en memoria), ahorrando CPU y memoria, y optimiza la conexión en el pool.

GitHub Actions y Flujos de Trabajo
developer-tests.yml (H2 en memoria)

Ubicación: .github/workflows/developer-tests.yml

name: Developer tests
on: push
jobs:
  launch-tests:
    runs-on: ubuntu-latest
    container: openjdk:8-jdk-alpine
    steps:
      - uses: actions/checkout@v2
      - name: Launch tests with Maven
        run: ./mvnw test

Claves: Corre con el perfil por defecto (dev con H2). Muy rápido para feedback continuo.

integration-tests.yml (PostgreSQL real)

Ubicación: .github/workflows/integration-tests.yml

name: Integration tests
on: push
jobs:
  container-job:
    runs-on: ubuntu-latest
    container: openjdk:8-jdk-alpine
    services:
      postgres:
        image: postgres:13
        env:
          POSTGRES_USER: mads
          POSTGRES_PASSWORD: mads
          POSTGRES_DB: mads_test
        options: >-
          --health-cmd pg_isready
          --health-interval 10s
          --health-timeout 5s
          --health-retries 5
    steps:
      - uses: actions/checkout@v2
      - name: Launch tests with Maven
        run: ./mvnw test -D spring.profiles.active=postgres
        env:
          POSTGRES_HOST: postgres

Claves: Levanta un contenedor oficial de postgres:13, espera con pg_isready y conecta a través del host de red postgres.
